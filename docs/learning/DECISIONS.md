## 1. 技术决策

### 2026-10-12 · 使用「项目规则文件 + 项目记忆文件 + Git」模式

**决策**：项目根放 `AGENTS.md`，学习记忆统一放在 `docs/learning/` 下，所有机制文件纳入 Git 版本管理。

**为什么**：
- 单靠一段超长提示词无法持久保存每天变化的项目状态。
- 不同 AI 插件对规则文件的自动加载位置不同，记忆文件位置由我们约定，规则文件位置由插件决定，二者解耦。
- Git 让我们能清楚看到 AI 改了哪些文件，避免无关改动。

**影响**：
- 第一次会话成本上升（要建文件 + 教 AI 读）。
- 后续任何新对话、新窗口都能从文件恢复上下文。
- 决策变更需更新本文件。

**替代方案考虑**：
- 只用超长提示词 → 记录容易失效，丢弃。
- 把记忆分散在各模块 README → 检索成本高，丢弃。
- 第三方记忆工具 → 引入额外依赖，丢弃。

### 2026-10-12 · 项目规则入口选 `AGENTS.md`

**决策**：通用规则放在 `AGENTS.md`，主提示词全文放在 `docs/learning/JAVA_RUOYI_MASTER_PROMPT.md`。

**为什么**：
- `AGENTS.md` 是事实上的跨工具标准，被 JetBrains AI Assistant / Aider / Cursor / Continue 等多个工具兼容。
- 学习方法的细节放在 `docs/learning/`，与项目规则解耦，方便后续单独更新。

**影响**：
- 不同 AI 插件可能默认读取的不是 `AGENTS.md`（例如 GitHub Copilot 读 `.github/copilot-instructions.md`）。届时根据插件实际情况调整，但 AGENTS.md 作为通用参考始终保留。

**待办**：
- [ ] 用户确认 IntelliJ IDEA 中安装的具体 AI 插件（决定是否有额外规则文件）

### 2026-10-12 · 不预先安装 JDK / Maven / 数据库

**决策**：在用户确认项目实际要求的版本之前，**不**下载安装 JDK、Maven、MySQL/PostgreSQL、Docker 等。

**为什么**：
- 避免安装错误版本，重复工作量。
- 避免对系统环境做大改动前未确认。
- 项目 clone 之后才能知道实际版本要求。

**影响**：
- 后续第一步必是「核对 README / pom.xml → 检查版本 → 在用户同意下安装」。
