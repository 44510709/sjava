## 1. 技术决策（已确认）

### 2026-10-12 · V2：采用「系统化 AI 开发与学习控制系统」

**决策**：从 V1 的"基础文件 + 记忆"升级为"7 类信息 + 3 类记忆 + 11 章规则"。

**为什么**：
- V1 缺少**训练协议**和**阶段路线图**，AI 教学容易跑偏。
- V1 缺少**长期使命**独立文件，AI 容易用短期任务覆盖长期目标。
- V1 的"任务文件"和"记忆文件"职责不清，单文件容易覆盖。
- 用户明示要求"形成目标 / 训练 / 记忆三个闭环"。

**影响**：
- 文件数量从 9 个增加到 13 个（+ JAVA_RUOYI_MASTER_PROMPT.md）。
- 每个 AI 会话开始要读更多文件，但每条都是必要的指针。
- 学习档案 / 训练协议 / 路线图独立后，更新不会污染其他内容。

**替代方案考虑**：
- 只升级一份"超级文件" → 失去职责分离，丢弃。
- 加记忆库（向量库）→ 引入额外依赖，丢弃。
- 把所有规则塞进 CLAUDE.md 一份 → 不跨工具，丢弃。

---

### 2026-10-12 · V2：AI 工具选定 Claude Code

**决策**：使用 **Claude Code**（Anthropic CLI）作为 AI 协作工具。

**为什么**：
- 用户 2026-10-12 明确表态"目前就先用 Claude Code"。
- Claude Code 可在终端独立运行，与 IDE 并存时规则文件统一为 `CLAUDE.md`。
- Claude Code 直接读项目文件、执行命令，能力强。

**影响**：
- 入口文件 `CLAUDE.md`，与 `AGENTS.md` 并存（不重复内容）。
- 跨工具的 `AGENTS.md` 保留，便于将来切换或并行使用其他 AI。
- **不再**依赖 IntelliJ IDEA 内嵌 AI 插件；用户需确认 IDE 与 Claude Code 协作方式（CLI 开在终端 vs IDE 内集成）。

**替代方案考虑**：
- Continue / Copilot / JetBrains AI Assistant 等 IDE 内嵌插件 → 用户已选 Claude Code。
- 纯 IDE 工作流 → Claude Code 还需要终端，丢弃"纯 IDE"假设。

### 2026-10-12 · V2：删除 NEXT_STEP.md，统一到 CURRENT_TASK.md

**决策**：删除 `docs/learning/NEXT_STEP.md`，统一用 `docs/learning/CURRENT_TASK.md`。

**为什么**：
- 两个文件记录同一件事会出现内容不一致。
- `CURRENT_TASK.md` 更明确表示"当前 / 正在进行"。

**影响**：
- CURRENT_TASK.md 结构包含"下一步操作"和"下一任务占位"，覆盖原 NEXT_STEP 的功能。
- 老 NEXT_STEP.md 已经并入 CURRENT_TASK.md，不丢信息。

---

### 2026-10-12 · V2：AGENTS.md 与 CLAUDE.md 不重复

**决策**：`CLAUDE.md` 是 Claude Code 轻量入口指针；`AGENTS.md` 是 11 章详细跨工具规则。

**为什么**：
- Claude Code 主要读 `CLAUDE.md`，重复会让会话变长。
- `AGENTS.md` 保留以适应跨工具场景（其他插件 / 规则系统可参考）。

**影响**：
- Claude Code 会话：先 `CLAUDE.md` 入口，再按指针读 `AGENTS.md`。
- 其他 AI 工具：可直接读 `AGENTS.md` + 各 `docs/` 文件。

### 2026-10-12 · V1：不预先安装 JDK / Maven / 数据库

**决策**：在用户确认项目实际要求的版本之前，**不**下载安装 JDK、Maven、MySQL/PostgreSQL、Docker 等。

**为什么**：
- 避免安装错误版本，重复工作量。
- 避免对系统环境做大改动前未确认。

**影响**：
- 后续第一步必是「核对 README / pom.xml → 检查版本 → 在用户同意下安装」。
- 仍未执行；取决于 V2 后的"环境检查"任务。
