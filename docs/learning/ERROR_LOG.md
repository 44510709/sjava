# ERROR_LOG · 错误与修复记录

> 记录**已解决**的重要问题。强调证据、根因和验证。
> 重要问题（影响业务、难以复现、安全相关）必须记录。
> 临时小问题（如打错字）可不上本文件。
>
> **使用方式**：先填 §1 修复前说明，再动手；修完填 §2 修复后记录。

---

## 1. 修复前强制说明（动手之前必填）

**凡涉及 Bug 调查或修复的任务，AI 必须先输出以下 5 项，再写代码：**

```markdown
### 问题原因：
（带证据的初步判断，区分已确认 vs 假设）

### 支持证据：
（日志片段 / 接口返回 / 实际复现步骤 / 文件引用）

### 修改位置：
（要改的真实文件路径，路径必须来自实际项目）

### 修改方案：
（要改的内容、改动的范围）

### 潜在影响：
（可能受影响的相邻功能 / 数据 / 权限）
```

**铁律**：未填修复前 5 项就动手 = 越权；必须先获得用户对方案的确认。

## 4. 常见错因速查（逐步补充）

| 症状 | 常见根因 | 第一步排查 |
|---|---|---|
| 启动报 ClassNotFound | 依赖未下载 / 模块未引入 | `mvn clean install -U` |
| 接口 404 | Controller 路径或包扫描错 | 确认 `@RestController` 与 `@RequestMapping` |
| 接口 500 | Service 异常 / SQL 错误 | 看后端日志和 SQL 日志 |
| 数据查不到 | 权限过滤 / 多租户过滤 | 看实际 SQL 是否带 where 条件 |
| 权限被绕过 | 用 List 入参 `@RequestParam` 没解析 | 加 `@Validated` |
