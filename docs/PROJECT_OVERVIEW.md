## 1. 长期使命

**用户的核心目标（2026-10-12 明确）**：

> **快速掌握 Java 后端开发，借助若依等框架快速搭建业务系统，知道怎么开发业务、怎么排查问题、怎么修复 Bug。**

具体含义：

- 借助框架（若依）能**快速搭建**业务系统（不是从零写）。
- 知道业务功能**怎么开发**：定位代码位置 → 修改 → 验证。
- 知道**怎么排查问题**：看日志、找 SQL、定位异常。
- 知道**怎么修复 Bug**：能描述现象、复现、定位、修复、回归。

业务系统目标：基于若依二次开发一套支撑日本代购业务的系统，
覆盖订单、采购批次、收货、物流、费用、对账等核心环节。

AI 的双重任务：

1. **快速**帮助完成实际开发任务（不拖泥带水）。
2. 在完成中训练用户**真正掌握**关键能力（不只背概念）。

判断成功的标准：**用户能用框架快速搭建业务 + 独立排查 / 修复 Bug**。

## 2. 业务系统大致需求

> 待 clone `sjava` 仓库后细化。下面只是**初始范围**，不锁定。

### 2.1 核心业务流

- **客户下单**：订单 + 明细
- **日本采购**：批次 + 明细
- **关联**：订单商品 ↔ 采购商品
- **收货**：日本仓库收货 + 异常处理（漏收 / 错收 / 损坏）
- **物流**：国际物流批次 + 国内配送
- **费用**：商品款 / 服务费 / 运费 / 补款 / 退款
- **对账**：交易、支付、物流数据三方核对
- **海关数据**：按需接入（待确认是否需要）

### 2.2 系统功能目标

- 多对多关系清晰（订单 ↔ 批次）
- 状态可追溯、状态机明确
- 金额计算精确、可审计
- 权限可控、数据可脱敏
- 异常路径有记录、可重试

## 3. 系统边界（必须明确）

### 3.1 AI 不能擅自动的事

- **业务规则**：由用户最终确认；AI 提供方案与代码，不替代人判断。
- **资金逻辑**：支付、退款、补款、汇兑；任何金额计算逻辑的最终拍板由用户决定。
- **数据结构变更**：表结构 / 关键字段 / 索引变更由用户决定。
- **申报模式**：海关、税务、对外数据接口的合规判断由用户决定。
- **生产环境操作**：部署、回滚、备份恢复、生产数据库查询。

### 3.2 AI 可以协助的事

- 标准 CRUD
- 简单查询和 SQL（必须走 `${}` 白名单）
- 前端页面
- 测试用例
- 文档和部署脚本

### 3.3 高风险操作（必须先列风险和回滚方案）

- 任何支付相关改动
- 任何订单状态机的修改
- 任何数据库结构变更
- 任何权限相关改动
- 任何批量数据修改
- 任何生产环境操作

## 4. 训练目标

最终用户应能够：

1. 熟悉真实项目目录。
2. 找到业务功能对应的文件。
3. 理解常见后端调用链。
4. 判断哪些文件应该修改。
5. 解释关键代码的作用。
6. 使用证据定位常见 Bug。
7. 审查 AI 的代码修改。
8. 进行接口测试和数据库验证。
9. 理解事务、权限、金额和数据一致性。
10. 使用 Git 管理代码。
11. 完成基本部署、日志检查和数据库恢复。
12. 独立维护自己的业务系统。

具体路线见 `docs/learning/ROADMAP.md`。
训练方式见 `docs/learning/TRAINING_PROTOCOL.md`。
